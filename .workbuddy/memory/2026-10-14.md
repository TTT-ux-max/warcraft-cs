## 1.27a 控制台残留 — 改为逆向：GL 提交处按几何吞掉（替代 CS 底板）

- 用户否决底板方案（"CS 风格深色面板盖住这个方案不行，要逆向解决"），已删除 `Overlay.cpp` 中的底板绘制块。
- 逆向结论：1.27a 控制台/皮肤确实走 `glDrawElements`（客户端顶点数组，GL_TRIANGLES，2D 四边形，6~96 index），经 `0x0F1783`/`0x0F1B47` 助手；**决定性判据**是投影矩阵：世界批次是透视（`projection[11]!=0`），控制台是正交（`projection[11]==0 && projection[15]==1`）。帮助定位的方法：`.local/glcallsites.py`（静态列出 Game.dll 全部 opengl32 调用点）+ 运行时 `_ReturnAddress()` ring dump + 栈扫描（UI 链 `0F1783→0E3530→7050B9→73784D/737770/7369D4→3630BE→368256`，世界链 `0F1783→13A6C3→1381AF→13980F`）。
- 实现：`PluginRuntime.cpp` 新增 `BatchInConsoleStrip(count,type,indices)` —— 正交投影 + 顶点数组全部投影进 `FullscreenView::ConsoleStrip()` 条带（容差 `max(12, strip*0.1)`）则吞掉；另加"低矮小四边形"规则（`count<=16 && maxY<=strip*1.6f`）覆盖皮肤顶梁。命中时先交给 `minimap.Submit`（与 1.26a UIHook 同路径）再 return。
- 顺带修好 1.27a 原生小地图：`PresentFrame` 在 `!originalWorld` 时 `minimap.BeginFrame`，`FinishFrame` 改为无条件；`NativeMinimap` 加 `capturedAny_/cleared_`，letterbox 清屏改为"首次抓到地图批次后"惰性执行（否则左侧留黑块）。
- 验证：DotA(geo4) 与真三(geo5/geo6) 条带内为纯 3D 世界、无残留无黑块，F6 往返稳定，RTS 控制台完好，ERROR=0。注意 `bandtest.ps1` 若测试期间桌面有窗口抢前台，截图会被污染（geo5 的 B/C 就是被 IDE 推送窗口盖住），已改为每次截图前重新 Focus。
- 清理：临时探针（ring/RLE dump/stackprobe/11 个 GL 入口钩子/`InstallConsoleDrawProbe`/`intrin.h`）已全部移除。
- 产物：`tools/build.ps1 -OutputDirectory F:\PY\cs\build2` 编译成功（0 警告），新目录 `build2/` 已加入 .gitignore；`build2` 需预置 `WarcraftOriginalMss.dll`（原始 Miles），不可用 `Mss32.dll`（那是本模组 loader，会被误当原件）。

## 排查：F6 按了没反应 = 用 D3D 启动了

- 现象：用户双击桌面 `Frozen Throne.exe` 快捷方式，进图后 F6 无效。日志（`WarcraftCS/WarcraftCS.log`）只有 116 行且**停在初始化**，完全没有 `render frames=` 帧记录、也没有 `control key=70 ...`（F6=0x46=70）按键记录。
- 根因：进程命令行是 `"...\war3.exe"`，**没有 `-opengl`** → 1.27 默认走 Direct3D9（本客户端还装了 ENB 的 `d3d9.dll` 代理 + `WarcraftHelper.dll`）。而 1.27a 分支的帧锚点是 `wglSwapLayerBuffers`（`PresentFrame` → 窗口子类化 → 输入），只在 OpenGL 下触发；D3D 下模组加载了但完全静止，F6 连 WindowProc 都到不了。
- 判据要点（可复用）：日志无 `render frames=` 且无 `control key=` → 模组没接管渲染，先查启动参数而不是查按键绑定。
- 处理：游戏目录放了 `Start WarcraftCS (OpenGL).cmd`（`start "" war3.exe -opengl`）。桌面 .lnk 想改就直接在目标后加 `-opengl`（PowerShell 的 WScript.Shell COM 建快捷方式被安全策略拦，故用 .cmd）。
- 注意：ENB（`d3d9.dll`/`enbseries.ini`）只在 D3D 下生效，切 OpenGL 后画面风格会变；`WarcraftHelper.dll` 是 mix 加载器，不受影响。

## 顶部资源栏也按几何隐藏（踩了 WarcraftHelper 的坑）

- 现象：1.27a FPS 下屏幕**顶部**的原生资源/菜单栏仍在（1.26a 整个 UI 阶段吞掉所以没有）。探测
  （临时 topband trace）显示顶栏批次：整宽背景 `y=576..593` + 三块拼 `y=566..605`（**向上越出屏 12px**，
  被 GL 裁剪）+ 图标/文字小四边形，最深底边 `y=529`（顶部 64px 内），vp 恒为全客户区 `0,0 1064x593`。
- **第一次实现（直接跳过调用）立刻崩溃**：war3 FATAL ACCESS_VIOLATION，两次 IP `0x698889AB`/`0x69878984`
  都不在已登记模块内（自建 modules 基址日志：self/ijl15/game/helper），落在 ~0x698x = **OpenGL 驱动 ICD**，
  读的地址像被算坏的客户端顶点数组指针。根因：客户端 `ijl15.dll`（WarcraftHelper 宽屏改造）自己改写这些
  UI 批次并有逐帧簿记，调用"消失"会使其失步 → 转发的下一批次数组指针算错 → 驱动读野指针。
  （注意：底部条带的跳过是安全的，helper 不改写那些批次。）
- **正确做法：零面积 scissor 裁剪**——照常调用完整原始链（helper 簿记正常），仅用
  `glScissor(0,0,0,0)` + `GL_SCISSOR_TEST` 让该批次一个像素不画。规则：正交 && x 在屏内 &&
  `minY >= top-76 && maxY <= top+16`。高个子面板（任务框/多面板排行榜）底边远低于此带，不受影响。
- 实现：`BatchInConsoleStrip` 改名 `ClassifyUiBatch` 返回 0=保留/1=条带(走 minimap.Submit)/2=顶栏(零面积裁剪)。
- 验证：DotA + 真三，顶栏消失、底条纯世界、F6 多次往返稳定、RTS 顶栏与控制台完好、ERROR=0。
- 其他：新增初始化日志 `modules self=... ijl15=... game=... helper=... d3d9=...`（崩溃归因用，保留）；
  topband 临时探针已移除。build2 已同步最终产物。

## 1.27a FPS 血条修复（bar1/bar2/bar3）

- 现象：FPS 下所有单位血条不显示。日志 `health bars candidates=34 submitted=0`——枚举正常、一个都没提交。
- 根因 1：`WorldLabelView`（eye/yaw/pitch/aspect + active）只在 `WorldHook` 里构建，1.27a 无 WorldHook →
  `healthBarView.active` 恒 false。→ 抽成 `UpdateLabelView()`，`PresentFrame` 的 `!originalWorld` 分支也调用。
- 根因 2：实测 verticalFov/aspect/near/far 来自 1.26a 透视钩子（1.27a 签名不匹配未装）。
  → 在 `ClassifyUiBatch` 读投影处捕获：**透视批次且 viewport==全客户区** 的第一个批次即世界投影，
  解码 `n=m[14]/(m[10]-1), f=m[14]/(m[10]+1), vfov=2*atan(1/m[5]), aspect=m[5]/m[0]`，
  present 时发布到 healthNear/healthFar/healthVerticalFov/healthAspect（`ApplyCapturedProjection`）。
- 试错记录：先试了挂 `glMatrixMode`+`glLoadMatrixf` 钩子取"far 最大"的投影——不可靠（会抓到
  小地图/头像的 3D 投影，如 27.3°/1.348），世界投影必须从世界批次自身读。
- 1.27a 实测世界投影：verticalFov=41.7 aspect=2.278 near=100 far=10000（引擎自己算的 aspect，
  不是客户区 1.794，也不是条带视口 2.391——必须实测，不能推）。
- 验证：DotA `submitted=1..7`，截图绿色血条落在中性树人头部（fill 宽 21px = 62.4×血量分数，尺寸正确）；
