## 编译工具链现状（重要）

- 用户自备工具链在 `F:\PY\msvc`（MSVC 14.44.35207 + Windows SDK 10.0.26100.0），
  安装器引导程序在 `F:\PY\tools\vs_buildtools.exe`（4.4 MB），`F:\PY\tools\layout.cmd`
  目标组件是 `Microsoft.VisualStudio.Component.VC.14.44.17.14.x86.x64`。
- **该工具链目前是 x64-only，无法产出 32 位目标**：
  - 只有 `bin\Hostx64\x64` 与 `bin\Hostx86\x64`（两者都产 x64 码），**没有 `bin\*\x86`**；
  - `VC\Tools\MSVC\14.44.35207\lib\` 只有 `x64`，**没有 `lib\x86`**（缺 32 位 CRT：libcmt.lib 等）。
  - 实测：`cl.exe /c` 产出 obj 的 COFF `machine=0x8664`（x64）；`bin\Hostx86\` 下无文件（vcvars 脚本 0 字节）。
  - `Windows Kits\...\Lib\...\um\x86` 与 `ucrt\x86` **已经存在** → 缺的只有 VC 的 x86 目标工具集。
- 其他编译器：`D:\666\mingw64` 是 `x86_64-w64-mingw32`（仅 64 位），全盘无 i686 mingw / clang。
- **为什么必须是 32 位**：`war3.exe` 与 `Game.dll` 实测 PE 头 `machine=0x014C`、可选头 `PE32`，
  魔兽 1.27 是 32 位进程；模组产物（`WarcraftCS.mix`，实为被改名的 DLL）由启动器注入该进程，
  位数必须与宿主进程一致。x64 系统能跑 32 位程序（WOW64）≠ 64 位 DLL 能进 32 位进程。
- 结论：要真编译，只需补装 VC 的 **x86 目标**（`bin\*\x86` + `lib\x86`），无需 32 位的编译器程序；
  x64 宿主交叉编译到 x86 是常规做法，下载量远小于整套 Build Tools。

### F6 失效的真正根因与修复（已实机验证）
- **根因**：Game.dll 的每帧呈现走的是**自己的导入表项**（`call [IAT]`，1.27a RVA `0xF0CF8`，
  紧接 `glFinish` 之后；全模块仅此 1 处 `FF15` 引用 `wglSwapLayerBuffers` 的 IAT 槽）。
  MinHook 只改了 `opengl32.dll` 导出的函数入口，而 RTSS 之类的「呈现拦截器」在首帧之后
  把调用方的 IAT 项改写成了自己的桩 → 引擎从此绕过我们的 detour，**钩子装得上但只命中一次**。
- **修复**（`src/runtime/PluginRuntime.cpp`）：
  1. `FindImportSlot()` + `ClaimPresentImport()` 直接**接管 Game.dll 里 `wglSwapLayerBuffers`
     的 IAT 项**（`presentImport.slot/displaced`），对入口被改写免疫；若 displaced 既不是
     导出地址也不是自己，则视为第三方 interposer，用 `swapForward` 转发，不破坏它的 overlay。
  2. `PresentGuard()` 守护线程每秒核对该槽，被改写就抢回并记日志。
  3. `ForwardPresent()` 用线程局部 `depth` 保证一次 present 只下探一层驱动调用。
  4. HUD 抑制：1.27a 上 `UIHook`（`0x60C580` 签名不符）与 `WorldHook`（`0x395900` 无地址）
     都不可用 → `nativeUIPhase` 永远为假，GL 提交处的丢弃逻辑失效。改为 `SyncInterface()`
     调原生 `wc3::ShowInterface(FALSE, &fade)` 隐藏整个控制台；`fade` 必须**非零**
     （用 `0.1f`，`0.0f` 永远到不了渐隐完成态）；`selfInterfaceRequest` 标记自身请求，
     避免被 `InterfaceHook` 误判为地图过场；地图若把界面 show 回来则 `interfaceReassert` 重发。
- **武器模型**：`WarcraftCS\assets` 需要由客户端 `cstrike\models` 转换生成
  （`tools/export_models.py --cstrike <dir> --output "<client>\WarcraftCS\assets"`），
